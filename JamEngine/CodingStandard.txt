[struct vs class 선택 기준]
	- 클래스는 불변성이 있는 경우에 사용한다.
	불변성(invariance)이란 객체가 항상 특정 상태를 유지하도록 보장하는 것이다.
	일반적으로 데이터 필드가 서로 의존적인 경우에 불변성이 존재한다.

	예를 들어, std::vector의 경우도
	T* 와 size 멤버가 서로 의존적이므로 class로 구현되어 있다.

	그러나, std::pair의 경우는 멤버들이 서로 독립적이므로 struct로 구현되어 있다.
	
	불변성이 있는 경우 대부분 class를 사용하도록 한다.

NOTE) 불변성이 있는데도 struct를 사용하는 경우
	객체에 불변성을 보장해야할 경우. 어디에서 불변성을 보장할 것인지 명확히 해야한다.
	대부분의 경우 자기 자신이 보장하는 것이 좋다. 이 경우 class를 사용한다.

	그러나 외부에서 불변성을 보장할 수 있는 경우. struct를 사용한다.
	이는 흔치 않고 OOP에 위배된다. 그러므로 DDD 관점에서 설계하는 시나리오이다.
	예를 들어, 어떤 중앙 집중적인 클래스. 혹은 알고리즘이 불변성을 보장하는 경우이다.

	전자의 경우, 해당 라이브러리의 Renderer 클래스와 VertexBuffer, IndexBuffer 구조체가 있다.
	후자의 경우, 해당 라이브러리의 SubDivision 알고리즘과 Edge, Face, Vertex 구조체가 있다.

	VertexBuffer, IndexBuffer, Edge, Face, Vertex 구조체의 멤버들은 서로 의존적이기에, 불변성을 갖는다.
	그러나 Renderer 클래스와 SubDivision 알고리즘이 불변성을 보장하기에 struct로 구현되어 있다.
	실제로 이를 class로 구현하면 코드가 굉장히 복잡해진다.
	C++ OOP 관점이 아닌 DDD 관점에서 바라보면 바람직한 설계이다.

Q) struct이 함수를 포함해도 되는가?
A) 부분적으로 yes. 그러나 함수는 불변성(invariance)을 깨지 않는 경우에 한한다.

Q) struct은 상속을 포함해도 되는가?
	- 부분적으로 yes. 단, 객체지향스러운 행위를 포함하지 않는 경우에 한한다.
	객체 지향스러운 행위란, 다형성, 캡슐화, 추상화 등을 말한다.
	단순히 데이터를 묶기 위한 용도 혹은 SFINAE 용도로 상속을 사용하는 경우에는 struct를 사용한다.

[pointer vs reference 선택 기준]
	- 대부분의 경우 reference 를 사용한다.
	
Q) pointer를 사용해야하는 경우는?
	- nullptr 를 사용할 수 있는 경우 (가장 중요)
		단, 매개변수로 전달하는 경우에는 std::optional<T> 를 선호할 것
	- 배열을 가리키는 경우 (단, std::span을 선호할 것)
	- pointer 연산이 필요한 경우 (ex. 포인터 산술, 포인터 대입, 포인터 비교 등)
	- 메모리를 동적으로 할당하는 경우 (ex. new, delete 등)
	- 대상을 변경할 수 있는 경우
	- 출력 매개변수 (단, std::tuple을 선호할 것)

Q) 데이터 필드에 reference를 사용할 수 있는가?
	- no. 이 경우 pointer를 사용한다.
	reference를 사용할 경우. 기본 생성자, 대입 연산자, 복사 생성자 등을 사용하지 못하게 된다.

NOTE) void의 경우 반드시 pointer를 사용한다. (void& 는 없기 때문. assert 체크 필요)

[정수 자료형 선택 기준]
 - 특별한 이유가 없는 한 Int32 를 기본으로 한다.
 - UInt32와 Int32를 섞어서 사용할 경우 산술 에러가 발생하므로 아예 Int32로 통일한다.
 - 음수가 필요없는 경우에도 UInt32 대신 Int32를 사용한다.
 - UInt32를 사용하는 경우는 비트마스크 연산을 하는 경우에 한정한다.
 - UInt8, Int8, UInt16, Int16는 struct 멤버로만 사용한다. 이것마저 피할 수 있으면 Int32로 통일한다.
 - std::vector, std::array, std::span 의 size는 UInt64인데, 이는 c++ 표준 라이브러리의 관례이다.
   만약 이들의 사이즈를 받아야 할 경우에는 Index 타입을 사용한다.
   Index 타입은 std::ptrdiff_t 이다.
   이것도 가능하면 Int32로 통일한다.

[exeption vs crash vs assert vs 에러코드]
1. exeption
	- 절대 사용하지 않는다.
	- 외부 라이브러리 혹은 std:: 라이브러리에 의해 예외를 처리해야 하는 경우
	  즉시 처리하여 예외가 전파되지 않도록 한다.
	- 예외를 처리하지 않는 이유는 성능 저하, 가독성 저하, 디버깅 어려움 때문이다.
	- 생성자에서는 부득히 하게 예외를 던질 수 밖에 없다.
	  Init 패턴을 사용하여 예외를 피하도록 한다.
	  예외를 던지지 않는다는 무언의 약속이 깨지기 때문이다.

2. crash
	- 특정 상황이 발생했을때 더 이상 어플리케이션이 정상적으로 동작할 수 없을 때
	  즉시 어플리케이션을 종료시킨다.
	- 해당 키워드는 거의 사용하지 않는다.
	- 메모리 할당 실패, 자원 획득 실패 등. 복구 불가능한 상황에서 사용한다.
	- crash를 사용하는 이유는 복구 불가능한 상황에서 계속 진행하는 것은
	  더 큰 문제를 야기할 수 있기 때문이다.

3. assert
	- 사용하는 용도 1: 절대 도달하지 말아야 하는 코드 영역
	- 사용하는 용도 2: 예측가능한 입력 값, 불변식, 출력 값 검증
	- 사용하는 용도 3: 기타 오로지 프로그래머의 실수로 인해 발생하는 상황 검증
	
	- 유의할 점: assert는 디버그 빌드에서만 활성화된다.
	  릴리즈 빌드에서는 비활성화되므로, assert에 의존하는 코드는 작성하지 않는다.

4. 에러코드
	- public 함수의 입력값 검증의 경우 에러코드를 반환한다.
